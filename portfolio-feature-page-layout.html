VẤN ĐỀ & GIẢI PHÁP

Marketing tự cập nhật nội dung trong một ranh giới an toàn.

Trang chủ có các khối banner, danh mục, sản phẩm và nội dung giới thiệu. Thay vì cho admin nhập template hoặc HTML tùy ý, hệ thống dùng một danh sách block được định nghĩa trước. Admin sắp xếp/ẩn hiện block, cập nhật nội dung banner và chọn ảnh từ File Manager; frontend chỉ render các component React đã được cho phép.

02 / API CONTRACT

Admin ghi có kiểm soát; public chỉ đọc nội dung đã phát hành.

Tất cả API dùng envelope chung của dự án: success, statusCode, message, data, timestamp, path.

Method & endpointQuyềnMục đích
GET /api/v1/admin/settings/layout/homeAdmin · JWT + PermissionGuardLấy bản nháp, bản public hiện tại và version.
GET /api/v1/admin/settings/layout/home/historyAdmin · JWT + PermissionGuardTra lịch sử lưu nháp / xuất bản, actor và thời điểm.
PATCH /api/v1/admin/settings/layout/home/draftAdmin · JWT + PermissionGuardValidate, lưu bản nháp mới và ghi revision.
POST /api/v1/admin/settings/layout/home/publishAdmin · JWT + PermissionGuardChuyển snapshot nháp thành cấu hình public, sau đó revalidate cache tag.
GET /api/v1/client/settings/page-layout/homePublic · read-onlyChỉ trả cấu hình đã xuất bản; chưa publish thì trả 404 để FE dùng bố cục mặc định.

03 / CẤU TRÚC DỮ LIỆU

Schema có version và audit, còn JSONB giữ cấu hình block có kiểm soát.

JSONB phù hợp vì mỗi loại block có một bộ trường khác nhau; các trường vòng đời và khóa trang vẫn là cột quan hệ có kiểu dữ liệu rõ ràng.

Block contract · allowlist phía BE

key chỉ nhận: hero, categories, about, marquee, promotion-banners, new-arrivals, campaign, featured-products, testimonials. Mỗi block có enabled; trường nội dung tùy loại gồm title, subtitle, description, image, buttonText, buttonHref, items[] hoặc banners[].

Mỗi banner có badge, title, buttonText, buttonHref, image và discountText. BE giới hạn độ dài, số block/banner và chỉ nhận URL http/https hoặc đường dẫn nội bộ.

Media reference: hiện tại cấu hình lưu đường dẫn/URL ảnh do File Manager trả về, chưa lưu mediaId và khóa ngoại. Nếu cần chặn xóa ảnh đang được dùng hoặc truy vết media chính xác, nên lưu ID tài sản và kiểm tra quan hệ trước khi publish.
04 / KIẾN TRÚC BE & FE

FE điều khiển nội dung; BE giữ quyền quyết định dữ liệu public.

BACKEND · NESTJS / PRISMA

Validate · authorize · publish

  • page-layout.dto.ts: schema Zod strict, allowlist block, kiểm tra URL và giới hạn payload.
  • settings.controller.ts: API admin có JWT + PermissionGuard; public chỉ có GET.
  • page-layout.service.ts: tách hành vi đọc nháp, ghi nháp, xuất bản và phát cache tag.
  • page-layout.repo.ts: transaction PostgreSQL, so sánh version nguyên tử và ghi history.
  • Publish sao chép draft → published; bản nháp không đi qua public endpoint.
FRONTEND · NEXT.JS / REACT

Admin editor · live preview · public renderer

  • /admin/page-layout: route quản lý giao diện riêng ngoài Cài đặt và Dashboard; sidebar dẫn thẳng tới editor.
  • HomeLayoutEditor.tsx: đổi thứ tự, bật/tắt block, sửa banner và chọn ảnh từ File Manager.
  • Nút xem trước mở storefront trong iframe và gửi bản nháp qua postMessage cùng origin; không lưu nháp tạm hoặc làm mới cache public.
  • HomeLayoutPreviewBridge.tsx kiểm tra origin, nguồn gửi và allowlist block, rồi đưa bản nháp vào chính renderer trang chủ.
  • setting.api.ts: gọi API admin qua client có access token; TanStack Query quản lý dữ liệu riêng trong admin.
  • app/(client)/page.tsx: server nạp cấu hình public cùng dữ liệu trang chủ.
  • public-data.ts: Next.js Data Cache 300 giây, tag page-layout-home; route trang chủ tái tạo tối đa sau 60 giây.
  • HomePage.tsx: map key sang component React cố định; section chưa cấu hình thì giữ fallback hiện tại.
Admin publish→BE commit DB→Revalidate Next tag→Request public kế tiếp nhận cấu hình mới
05 / QUYẾT ĐỊNH PRODUCTION

Các ranh giới quan trọng của một CMS nhỏ.

Block registry, không render tùy ý

FE chọn component từ danh sách cố định. Không lưu PUG filename, JavaScript, HTML tùy ý hoặc dùng dangerouslySetInnerHTML để dựng trang.

Draft và published độc lập

Lưu nháp không làm thay đổi storefront; publish là hành động riêng, có actor, timestamp và snapshot revision.

Chống ghi đè đồng thời

Client gửi expectedVersion; database cập nhật có điều kiện theo version đang đọc. Một người lưu sau không âm thầm xóa thay đổi của người trước.

Cache public, không cache admin

Chỉ dữ liệu đã xuất bản đi vào Next.js shared cache. Sau khi DB commit, BE yêu cầu Next.js revalidate đúng tag; TTL là đường dự phòng.

Fallback giữ site hoạt động

Chưa có bản public hoặc API lỗi thì trang chủ dùng bố cục mặc định đang có, tránh một cấu hình thiếu làm trắng toàn trang.

Xem bản nháp bằng renderer thật

Preview dùng chính các section React của storefront trong iframe cùng origin. Bản nháp không publish, không chạm shared cache và không tạo thêm bản ghi server.

JSONB có giới hạn miền

JSONB linh hoạt cho các block khác hình dạng, nhưng field vẫn được Zod kiểm soát. Khi cần query/report theo field, hoặc số loại block tăng lớn, tách sang bảng có kiểu cụ thể.

CÁCH TRÌNH BÀY KHI PHỎNG VẤN

“Tôi xây CMS trang chủ theo block registry thay vì cho phép render template tự do. Backend validate schema và quyền, lưu riêng draft/published bằng JSONB, dùng version để tránh lost update và ghi revision phục vụ audit. Frontend render component React đã allowlist; public data được cache ở Next.js và tag được invalidated sau publish.”
