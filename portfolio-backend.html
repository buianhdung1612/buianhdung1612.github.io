TEDDYPET · COMMERCE API

Ecommerce Backend

A domain API that keeps catalog, stock, customer, and order rules consistent across the client storefront and admin console.

Detailed note, written in English. The Vietnamese case study summarises this page. API Design → · Thiết kế API →
01 / DOMAIN API

One validated API boundary for both applications.

NestJS modules expose ecommerce capabilities through REST endpoints. The API validates incoming data at the request boundary, applies business rules in services, and persists relational domain data with Prisma and PostgreSQL.

FrameworkNestJS · TypeScript
ValidationZod DTOs
Data accessPrisma ORM
DatabasePostgreSQL
02 / DOMAIN RESPONSIBILITIES

Model the rules the UI depends on.

01 Catalog & variants

Products, categories, brands, and SKUs form the catalog used by the client and admin applications. Variant and stock data are connected to the parent product rather than duplicated into separate frontend models.

02 Inventory & pagination

Stock filtering aggregates quantities across SKUs before the API paginates results. This keeps totals and page boundaries correct for admin filters and avoids filtering only the currently visible page.

03 Cart & orders

Order creation is server-authoritative: submitted cart intent is validated against current product, price, and stock rules before a durable order is created.

04 Reviews & content

Review and blog endpoints support the customer-facing experience and store administration, with resource-oriented API contracts for queries and writes.

03 / ENGINEERING DECISIONS

Protect consistency at the service boundary.

01

Validate untrusted input at the edge. Zod schemas define accepted request shapes before domain services work with them.

02

Keep the database relational. Prisma models product, SKU, cart, order, and customer relationships in PostgreSQL.

03

Aggregate before paging. Inventory-aware filters run against the full matching data set, so API totals agree with the page contents.

04

Keep media references lightweight. The commerce API stores stable file paths returned by File Manager; binary file bodies belong to the dedicated media service.

04 / JWT AUTHENTICATION

A short-lived JWT session with refresh-token rotation.

The flow validates credentials, issues a signed access JWT, protects API requests, and renews the session through a rotating HttpOnly cookie.

Authentication and authorization are separate checks.JwtAuthGuard verifies the signed access JWT and expiry. PermissionGuard checks the active account and its API permission before the protected operation runs.

INTERVIEW WALKTHROUGH

“I use a short-lived signed JWT for API authentication and keep it in memory. A separate HttpOnly refresh JWT renews the session; the database stores only its SHA-256 hash, and rotation is atomic to prevent token reuse. Every protected operation verifies identity first, then checks the account’s API permission. File Manager handles media bytes while the commerce API remains authoritative for inventory and order rules.”
