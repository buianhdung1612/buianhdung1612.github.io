TEDDYPET · CLIENT APPLICATION

Customer Storefront

A responsive shopping experience that guides customers from product discovery through checkout and post-purchase reviews.

Detailed note, written in English. The Vietnamese case study summarises this page. Storefront & Admin → · Storefront & Admin →
01 / PRODUCT GOAL

Make product discovery feel simple.

The customer app brings categories, brands, product details, cart, checkout, orders, and reviews into one connected journey. Product and availability information comes from the commerce API, while cart interactions stay responsive on the client.

FrameworkNext.js · React · TypeScript
Kết xuất và cache serverNext.js SSR · ISR · Data Cache
Cache dữ liệu trình duyệtTanStack Query
Trạng thái tương tác cục bộZustand
02 / CUSTOMER JOURNEY

One experience, from browse to review.

Each step uses the same product and order domain exposed by the backend.

01 Discover

Browse by category or brand, search the catalog, and narrow a result set with filters and pagination. URL and request state should describe the same selected view so it can be refreshed and shared consistently.

02 Evaluate

Product detail brings together descriptions, variants, images, SKU availability, and customer reviews. The page uses remote query data and explicit loading, empty, and failure states.

03 Purchase

The cart supports immediate quantity and item updates. Checkout gets a signed GHN quote, refreshes it before expiry, and submits it with an idempotency key. The commerce API remains authoritative for prices, inventory, shipping fees, and order creation.

04 Follow up

Customers can review their order history and submit product reviews. After a successful write, the relevant order or review views are refreshed from the server.

03 / KIẾN TRÚC FRONTEND

Tổ chức theo nghiệp vụ để thay đổi có phạm vi rõ ràng.

Client và Admin dùng cùng nguyên tắc: route xác định trang cần hiển thị; mỗi feature sở hữu giao diện, API và trạng thái của nghiệp vụ đó.

Next.js App RouterURL · layout · metadata · server data
Business featuresCheckout · Order · Product · Auth
Hạ tầng dùng chungHTTP client · API contract · UI chung

01 Mã nguồn đi cùng nghiệp vụ

Client và Admin đều chia theo feature. Route giữ URL và ranh giới render; feature sở hữu màn hình, hook, logic và API adapter của nghiệp vụ.

02 Tái sử dụng có phạm vi

Form tạo/sửa địa chỉ dùng chung một implementation; form tạo/sửa sản phẩm Admin cũng vậy. Checkout tách màn hình, form địa chỉ, hook điều phối và hook bản đồ; Checkout và Address Book dùng cùng adapter Goong. Order Detail tách điều phối, stepper và dialog review; File Manager tách truy vấn/thao tác, chế độ list/grid và các hộp thoại.

03 Contract tách khỏi biểu mẫu

Mỗi feature giữ API adapter và contract riêng. Kiểu sinh từ OpenAPI giúp FE tích hợp theo hợp đồng BE; trạng thái form không trở thành schema API.

04 Kiểm tra ranh giới tự động

Architecture check chạy trước build: chặn import chéo Client/Admin, import từ đường dẫn cũ và request HTTP trực tiếp trong UI/hook feature. TypeScript và OpenAPI contract check kiểm tra kiểu dữ liệu.

Đánh đổi: Cấu trúc này tăng số thư mục và import. Feature nhỏ chỉ tạo những phần thực sự cần; không áp dụng đủ mọi lớp cho từng màn hình.

04 / PHÂN CHIA TRẠNG THÁI

Dữ liệu từ server và trạng thái tương tác có vai trò riêng.

01

Dữ liệu trang công khai được lấy trên server. Next.js gọi và cache danh mục, sản phẩm, bài viết rồi gửi dữ liệu đầu tiên cùng trang đã kết xuất.

02

TanStack Query quản lý dữ liệu phía trình duyệt. Nó nhận dữ liệu ban đầu và điều phối refetch, trạng thái tải, cũng như cập nhật sau hydrate.

03

Zustand quản lý tương tác giỏ hàng cục bộ. Giao diện phản hồi nhanh, còn BE vẫn xác thực tồn kho và tạo đơn hàng.

04

Mỗi tầng cache có vòng đời riêng. Làm mới cache Next.js không tự đẩy dữ liệu mới vào query cache của tab đang mở.

05 / RENDERING

Chọn cách render theo nhu cầu của từng trang.

Trang cần SEO lấy nội dung trên server; màn hình cá nhân hóa ưu tiên tương tác phía client. Render và cache là hai quyết định liên quan nhưng có vòng đời riêng.

01 Trang chủ · ISR

Trang chủ là nội dung công khai, cần tải nhanh và hỗ trợ SEO. Next.js tái sử dụng kết quả render tối đa 60 giây trước khi làm mới.

02 Danh sách · SSR theo URL

Trang sản phẩm và bài viết đọc bộ lọc từ query string, render kết quả theo URL để liên kết có thể chia sẻ và tải trực tiếp. API data vẫn được cache theo TTL.

03 Chi tiết · SSR theo slug

Next.js render theo request và tạo metadata SEO cho slug được yêu cầu. Không có generateStaticParams nên route này không phải ISR; response API vẫn được Data Cache 60 giây.

04 Trang nội dung · ISR

/about, /faq và /stores lấy nội dung đã xuất bản từ CMS, render trên server và tái tạo tối đa sau 300 giây. Metadata SEO dùng cùng nguồn nội dung.

05 Liên hệ · Dynamic render

/contact render theo request. Dữ liệu liên hệ lấy qua server fetch và được Next.js Data Cache tối đa 300 giây theo tag site-settings.

06 Chính sách · SSR theo loại

/policy/[type] chọn nội dung đã xuất bản theo loại chính sách ở mỗi request. Dữ liệu trang được cache 300 giây theo tag content-pages; loại không hợp lệ hoặc chưa xuất bản trả về 404.

07 Dữ liệu riêng · Client-side fetch

Giỏ hàng, checkout, dashboard và màn hình quản trị (bao gồm trình chỉnh sửa Cài đặt) cần phiên đăng nhập nên tải dữ liệu sau hydration, không đưa vào public cache. Đây không phải CSR thuần toàn trang.

06 / FE CLIENT

Chiến lược cache dữ liệu bên FE Client

Next.js cache dữ liệu công khai ở server để render trang nhanh. TanStack Query tiếp nhận dữ liệu ban đầu và quản lý các lần đọc tiếp theo trong trình duyệt.

01 Render và cache server

Trang công khai lấy dữ liệu bằng server fetch. Next.js cache sản phẩm, bài viết, cài đặt website và nội dung đã xuất bản theo TTL/tag; dữ liệu ban đầu được gửi cùng HTML để trang hiển thị sớm.

02 Cache truy vấn trình duyệt

TanStack Query giữ cache riêng trong từng trình duyệt. Cài đặt liên hệ ở client có query key client-settings-general và stale time 5 phút; màn hình admin cũng tải dữ liệu bằng query riêng sau đăng nhập.

03 Tag cho nội dung Cài đặt

Cài đặt website dùng tag site-settings; nội dung trang tĩnh đã xuất bản dùng content-pages. Cả hai có TTL 300 giây và không đưa bản nháp vào API public.

04 Đồng bộ sau cập nhật

Khi admin lưu cài đặt hoặc nội dung, BE gọi endpoint revalidate nội bộ để hết hạn tag tương ứng ở Next.js; query của màn hình admin cũng được invalidate để đọc lại. Browser cache của người đang mở trang làm mới ở lần fetch kế tiếp, không tự bị đẩy dữ liệu tức thời.

Phạm vi: Cache này dành cho dữ liệu công khai. Tài khoản, giỏ hàng và checkout không dùng chung cache công khai.
TÓM TẮT KIẾN TRÚC

“Tôi dùng Next.js để kết xuất nội dung công khai trên server và cache API theo TTL/tag. Dữ liệu ban đầu được truyền sang TanStack Query để quản lý ở trình duyệt; BE chủ động làm hết hạn cache server sau khi ghi dữ liệu. Với đơn hàng, BE vẫn là nguồn xác thực cuối cùng cho giá và tồn kho.”
