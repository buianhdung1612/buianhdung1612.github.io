TEDDYPET · STOREFRONT & ADMIN

Frontend có ranh giới rõ ràng

Một ứng dụng Next.js phục vụ cả storefront và trang quản trị, với quy tắc kiến trúc làm hỏng build khi vi phạm.

IMPLEMENTED · STATIC CHECKS PASSED (2026-11-06)Next.jsReactTanStack QueryZustand
TL;DR
Vấn đề

Frontend lớn dần sẽ mục khi các feature import lẫn nhau và component gọi mạng trực tiếp.

Cách giải

Hai ứng dụng trong một repo với quy tắc import bị ép, API adapter theo từng feature, type API sinh tự động và chiến lược render có chủ đích.

Bằng chứng

Kiểm tra kiến trúc, API version, API contract và tsc đều pass ngày 2026-11-06; 85 trang route.

01Vấn đề

Storefront cộng trang quản trị nhanh chóng thành hàng trăm file. Không có quy tắc, code admin rò vào bundle của người mua, component tự gọi dữ liệu, và cache hành xử khó đoán.

02Ràng buộc
  • Code storefront và admin không bao giờ import lẫn nhau.
  • Component và page không gọi mạng trực tiếp; request thuộc về API adapter.
  • Trang công khai phải nhanh và đủ mới mà không gọi API ở mỗi lượt xem.
  • Checkout phải khôi phục được khi mất phản hồi.
03Thiết kế

  1. Ranh giới được ép bằng script

    scripts/check-architecture.mjs chạy trước mỗi lần build: không import giữa client/ và admin/, shared/ không import cả hai, và page, component, hook của feature không được gọi fetch hay Axios client.

  2. State server và state cục bộ

    TanStack Query giữ dữ liệu server; Zustand giữ phiên và state UI cục bộ. Access token không được lưu bền và refresh được tuần tự bằng navigator.locks.

  3. Render có chủ đích

    Trang chủ dùng ISR, danh sách shop và blog render theo từng request, giỏ hàng, checkout và admin dùng query phía client. Dữ liệu công khai lấy bằng fetch chỉ chạy phía server qua Next.js Data Cache; Core gọi một endpoint revalidate có bảo vệ để hết hạn cache tag.

  4. Type sinh từ contract

    Type API được sinh từ file OpenAPI của backend, nên thay đổi backend gây vỡ sẽ làm hỏng bước kiểm tra frontend.

  5. Khôi phục checkout

    Checkout lưu idempotency key và payload trong session để mất phản hồi vẫn khôi phục được bằng cách gửi lại cùng request.

  6. Công cụ nội dung cho chủ shop

    Trình sửa bố cục trang sắp xếp và bật/tắt khối, xem trước bản nháp, xuất bản và làm mới cache công khai. Đánh giá sản phẩm đi qua kiểm duyệt. Giao diện có tiếng Anh và tiếng Việt.

05Kiểm chứng

Đã thể hiện

  • 85 trang route trên storefront và trang quản trị.
  • Gộp giỏ hàng khi đăng nhập, checkout khôi phục idempotency, trang kết quả VNPay, các tính năng CRUD admin, trình sửa bố cục trang và khung chat.
  • Kiểm tra kiến trúc, API version, API contract và tsc đều pass ngày 2026-11-06.

Chưa kiểm chứng / chưa có

  • Chỉ có năm file test, đều cho logic. Chưa có test component hay end-to-end trên trình duyệt.
  • Bảo vệ route admin chạy phía client; chưa có middleware phía server. API vẫn kiểm quyền.
  • Chưa có Dockerfile và CI (output: 'standalone' đã được đặt sẵn).
  • Hai chỗ lệch đã biết với backend: trang thông báo admin và lời gọi xoá thư mục.
06Đánh đổi

Một repo, hai ứng dụng

Công cụ và type dùng chung đơn giản, nhưng ranh giới phải do script canh giữ thay vì các package riêng.

Guard admin phía client

Làm nhanh, nhưng guard UI chỉ để trông ổn. Bảo vệ thật là permission guard của API.

Type được sinh tự động

Loại bỏ lệch pha, nhưng buộc phải chạy lại bước sinh sau mỗi thay đổi API.
